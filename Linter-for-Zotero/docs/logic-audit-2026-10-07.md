# 2026-10-07 逻辑链路检查与修复

本次检查以当前源码和独立 Zotero 测试资料库为依据，重点覆盖规则准备、适用性判断、并发执行、数据库保存、结果显示、通知注册和标题编辑器生命周期。保留现有规则架构，修复纳入补丁版本 10.0.5。

## 修复内容

| 链路 | 原问题 | 当前行为 |
| --- | --- | --- |
| 单元测试发现 | `**/*.test.ts` 同时收集 `.scaffold/publish` 中的旧项目副本，造成重复统计 | 只运行 `src/**/*.test.ts`；原先显示的 376 项实际包含两份各 188 项测试 |
| 规则适用性 | 字段适用性判断抛错会跳出整个条目的规则循环，后续规则和已修改条目的收集受影响 | 适用性判断与规则执行使用相同的异常隔离路径，记录失败后继续其他规则并统一保存 |
| 规则准备 | 准备失败只有报告，没有独立的批次统计；全部失败时提示“未选择条目” | 新增 `BatchResult.preparationFailed` 和 `skipped`，未准备的规则不会执行；全部准备失败时显示错误 |
| 进度显示 | 进度窗口异常可能使并发 worker 提前退出或导致数据库事务回退 | 初始化与更新异常单独记录，继续处理和保存；结果窗口异常不会改变保存结果 |
| 批次清理 | 结果窗口创建发生在状态与缓存清理之前，抛错后可能污染下一批 | 先清理状态和缓存，再显示结果；异步报告错误被捕获；静默批次保留记录而不打开报告窗口 |
| 关闭 | 等待队列的 Promise 拒绝会跳过进度窗口关闭并中断插件关闭流程 | 记录队列错误，仍完成 runner 的窗口清理 |
| 超时隔离 | Proxy 只保护赋值和修改方法，删除属性和定义属性可绕过超时限制 | 属性删除和重新定义同样受 AbortSignal 保护，执行结束后也不可修改 |
| 外部请求节流 | 提高条目并发会允许同一冷却区间内发出多个请求；同服务的标识符补全和数据获取分别节流 | 冷却间隔独立于条目并发，严格间隔发起请求；同一服务的两个入口共享节流队列 |
| 查重 | 一个文献库的查重异常被忽略，相关条目显示“无重复” | 按文献库记录失败，相关条目报告本地化错误，其他文献库和格式规则继续执行 |
| 通知器 | 重复初始化可能留下多个观察者；重复注销没有状态保护 | 注册前注销旧观察者；注销后清除 ID，重复初始化只保留一个观察者 |
| 标题预览 | 后台窗口的程序化焦点变化不发出 Gecko 焦点事件，后台刷新可能重建预览；原测试没有确认窗口实际获得焦点 | 收到焦点事件立即清理旧界面，只有实际获得焦点的标题编辑器才能创建或刷新预览；实机测试先确认文献库窗口焦点 |

## 行为与验证边界

- `passed` 和 `failed` 统计已经处理的条目；准备失败独立计入 `preparationFailed`。调用方应同时检查准备失败、取消状态和条目失败，不能仅依据 `failed === 0` 判断整个请求完成。
- 严格冷却间隔会使涉及外部 API 的高并发批次耗时增加；条目 worker 数量与 API 发起速率分别控制。
- 外部服务回归使用受控响应，确认回退和保存逻辑；没有据此认定各网站当前在线或响应数据一定完整。
- 规则失败前的同步修改继续保留，并与其他规则结果一起保存；未引入逐规则事务回滚。
- 永久保存失败仍会保留条目的内存变更并报告错误，需要核查或重试；没有将其视为已落盘。
- 真实运行时回归针对本机 Windows Zotero；其他平台与所有第三方插件组合尚未验证。
