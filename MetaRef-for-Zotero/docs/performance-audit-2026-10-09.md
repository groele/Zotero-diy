# MetaRef 12.1.0 逻辑、功能与性能检验

检验环境：Windows、PowerShell 7、Zotero 10.0.6、pnpm 12.3.4；生产 JavaScript 面向 Firefox 140。

本次基线为工作区开始时的 11.0.8 实现。发布前另行比对线上 12.0.0，保留其运行目标、预印本识别、标题工具栏及更新目录修复。基线测量不能视为对线上 12.0.0 安装包的直接性能测量。

## 发现与处理

| 检查对象 | 发现 | 处理 |
| --- | --- | --- |
| 新增事件 | Zotero 等待通知观察者，原回调等待延迟及整批整理 | 观察者立即返回，后台队列合并近邻事件 |
| 密集导入 | 多个通知触发多次准备、处理和保存 | 以条目 ID 去重，批次串行；处理中新增条目归入下一批 |
| 自动开关 | 等待期间可能关闭开关或删除条目 | 执行前重新检查开关、可编辑性、条目和群组状态；卸载清理待处理队列 |
| 数据加载 | 内置数据每批结束后失效，重复读取和建索引 | 保留固定内置缓存，自定义文件按批次释放；显式重读仍完整清缓存 |
| 进度显示 | 处理和保存每条记录均更新界面 | 同阶段每 100 毫秒刷新，阶段切换和完成强制刷新 |
| 设置联动 | 每次点击重新计算全部控件的依赖 | 初始化时计算一次，后续读取父开关状态 |
| 标题工具栏 | 延迟点击回调可在移开焦点后重新打开 | 管理并取消待打开回调，校验焦点和编辑器连接状态 |
| 窗口关闭 | 一轮原生结果窗口检验出现跟踪状态未释放 | 使用原生窗口关闭通知及独立完成承诺，释放观察者；文档 unload 不作为关闭条件 |
| 操作说明 | “常规检查不联网”与 DOI、缩写规则实现不符 | 说明可联网规则及其关闭入口；保留强功能 MetaRef 前缀 |
| 英文设置 | 较长的快捷键名称使行高超出紧凑布局 | 使用简短入口名称，并用完整提示说明范围 |
| 构建 | 无变化的规则声明也反复覆写，曾遇到 Windows 文件占用 | 仅在内容改变时生成，减少不必要写入 |

## 真实条目性能场景

测试在独立 Zotero 资料库保存 160 个真实期刊条目，完成后清理测试条目。使用相同场景测量优化前后：连续 8 次单条期刊缩写处理、160 条字段修改与事务保存、16 个新增通知以及一次原生通知派发。

| 指标 | 本地 11.0.8 基线 | 12.1.0 中文 | 12.1.0 英文 |
| --- | --- | --- | --- |
| 期刊数据读取次数 | 8 | 1 | 1 |
| 16 个新增事件产生的批次数 | 16 | 1 | 1 |
| 160 条处理的进度刷新次数 | 323 | 9 | 10 |
| 8 次缩写处理耗时（毫秒） | 667 | 238 | 229 |
| 160 条修改及保存耗时（毫秒） | 814 | 658 | 836 |
| 原生通知派发耗时（毫秒） | 653 | 94 | 124 |

原始数据见 [性能记录](assets/performance-v12.1.0.json)。次数断言验证：内置期刊文件最多读取 1 次、16 个新增事件合并为 1 批、160 条全部保存且没有遗留变更标志、进度刷新次数小于条目数。

通知派发测量包含 Zotero 的其他观察者；新增队列保留至少 500 毫秒的合并窗口。后台处理不等待通知事务，但并不取消队列延迟。单次耗时受磁盘、其他窗口、系统负载和运行顺序影响；次数及完整保存结果比单次耗时更适合判断这次优化。此次没有用结果证明所有文库规模都会按相同比例加速，也没有测量常驻内存峰值。

## 功能与错误路径

221 项单元测试覆盖标题规则、日期数字、标识符、数据集、缓存、并发、超时、队列及窗口生命周期。窗口测试保留此前场景，并增加原生提前关闭、其他窗口关闭不影响本窗口、文档卸载及工具包过早解锁不结束原生窗口等回归。

中文和英文真实 E2E 各 44 项，最终结果见 [验证记录](../dist/verification.json)。覆盖：

- 设置开关保存、群组联动、搜索展开、快捷键录制／禁用／重置／冲突及实际布局。
- 原生菜单连续执行、分类上下文、索引查询窗口反复开关、索引不污染条目元数据。
- 标题鼠标和键盘选区、嵌套格式切换、迅速移开焦点后的工具栏隐藏。
- 有界并发和批次串行、准备及单条规则错误隔离、取消、超时后拒绝晚到修改。
- 批量保存失败后的恢复、永久失败报告、整批撤销和重做。
- 自定义 JSON／CSV、编码容错、文件编辑后重读、无效数据回退及保留原路径。
- 元数据服务失败回退、空字段模式的字段和作者角色保留、预印本、PMID 和 URL 服务路线。
- 真实 PDF 导入及页码补全，以及把临时开发目录替换为生产 XPI 后检查身份、版本、内置资源和实际字段保存。

构建、插件和测试 TypeScript、ESLint、AutoCorrect 另行检验。发布包采用已通过真实安装验证的生产 XPI，并核对 SHA256、字节数、清单、版本、更新 URL 与下载路径。

## 尚未覆盖的范围

外部元数据服务用受控响应验证逻辑，没有检验所有服务的实时可用性和数据质量；内置数据库快照未在线刷新。macOS、Linux、全部第三方插件组合、大型文库的长期内存行为仍需专门实机验证。
